📚 資料室：なろう作品登録ギミック

Braveの共有シートからショートカットを実行し、作品を「ともたよむ」の本棚へ登録する仕組みの記録。

実機確認済み 通常作品・R18作品の取り込みと、登録後に本棚へ自動で戻る流れを確認（2026年10月24日）

1. 何ができる？

  • なろう作品ページからNコードを取り出す。
  • 登録ページでAPIから作品情報を取得する。
  • 本棚管理で指定した「📥登録先」へ作品情報を保存する。
  • 登録処理が終わると本棚へ自動で戻り、結果メッセージを表示する。
  • 検索除外作品は通常の登録手順とは別の例外項目として、項目7以降に手動登録の流れを記載。

2. ショートカットの流れ

  1. 共有シートから入力を受け取る
    Braveの共有シートから、登録用ショートカットを起動する。
  2. URLからNコードを検索
    正規表現 n[0-9]{4,}[a-z]+ でNコードのパターンを検索する。
  3. 一致したテキストのグループ0を取得
    一致したNコード全体を取り出す。
  4. 登録URLを組み立てる
    https://tomotaday.github.io/tomotayomu/register.html?ncode=取得したNコード
  5. URLを開く
    Brave内で登録ページが開き、Nコードを使って自動取得・登録を開始する。

3. 登録ページ側の処理

  1. Nコードを受け取る：URLの ncode パラメータから取得する。
  2. 作品情報を取得する：まず全年齢向けAPIを確認し、見つからない場合はR18向けAPIも確認する。
  3. 登録先を調べる：IndexedDBの shelf_names から work_add_target === true の棚を探す。
  4. 重複を確認する：works_cache や shelf_placement に既存データがある場合は、既存データを上書きしない。
  5. 新規作品を保存する：作品情報・棚への配置・取得できる作者情報をIndexedDBへ保存する。
  6. 結果を伝えて本棚へ戻る：結果コード付きで index.html に移動する。

4. 本棚に表示される結果

  • ok：作品を本棚に登録した。
  • exists：すでに登録済み。既存データは変更しない。
  • api_error：APIから作品情報を取得できなかった。
  • target_error：登録先の棚を確認する必要がある。
  • save_error：保存処理に失敗した。

本棚側は結果コードを日本語のメッセージに変換し、表示後にURLから結果コードを取り除く。表示処理は本棚の通常の再描画処理とは分けている。

5. 保存先と安全策

  • 本棚データの正本はブラウザー内のIndexedDB（DB名 tomotaYomuDB）。
  • 登録先は本棚管理で指定した「📥登録先」に従う。
  • 同じNコードが既に作品情報または本棚配置にある場合、新規登録せず既存データを保持する。
  • ショートカットはNコードを登録ページへ渡す役割。作品情報の取得・保存は register.html が担当する。

6. 動作確認の記録

  • 通常作品：登録画面を経由し、本棚へ自動復帰。成功メッセージと本棚への実追加を確認。
  • R18作品：取り込み成功を確認。
  • なろう公式アプリ：公式アプリから共有シートでショートカットを実行。URLに余分な情報が付いていても、Nコードを抽出して登録できることを確認。
  • 登録済み作品：重複登録防止の判定が働くことを確認。
  • 検索除外作品：通常の登録手順とは別の例外項目として、項目7以降に手動登録の流れを記載。

注：R18作品の取り込み成功は実機で確認済み。ただし、特定のテストについて、どちらのAPIが採用されたかや、保存された全フィールドを個別に検査したことまでは意味しない。

7. 検索除外作品を手動で取り込む流れ

検索除外作品は、通常のNarou API検索では情報を取得できないため、作品情報ページの表示内容（メタデータ）を使って手動登録する。

  1. 作品情報ページを開く
    Braveで対象作品の「作品情報」ページを開く。R18作品はムーンライトノベルズ等の該当ページを使う。
  2. 検索除外作品用ショートカットを実行する
    共有シートから入力を受け取り、入力内容からテキストを取得する。
  3. URLの内容を取得する
    ショートカット内のテキストを使ってURLの内容を取得する。表示されている設定では、方法はGET、ヘッダーに Cookie: over18=yes を指定している。
  4. 取得結果をクリップボードにコピーする
    「URLの内容」をテキストに入れ、そのテキストをクリップボードにコピーする。
  5. 新規登録画面を開く
    ショートカットの最後に「メタデータ新規登録」work_add.html を開く処理がある。
  6. 手動で貼り付ける
    新規登録画面の「受信メタデータ」欄にクリップボードの内容を手動で貼り付け、「メタデータを読み込む」を押す。なお、ショートカットがコピーする内容が登録用メタデータとして正しく整形されていることは、現時点では確認できていない。
  7. 内容を確認・補完する
    タイトル、Nコード、作者名、作者ID、取得元URL、あらすじなどを確認し、空欄や誤りがあれば修正する。
  8. 本棚に登録する
    登録ボタンを押し、完了メッセージを確認する。

現在の状況：ショートカットはクリップボードへのコピーと新規登録画面を開く処理を行う構成だが、コピーされる内容が登録用メタデータとして正しいかは未確認。新規登録画面への自動貼り付けは未実現のため、現時点では内容を確認して手動で貼り付ける。

8. メタデータ新規登録ページの構成と仕様

対象ファイル：work_add.html（メタデータ新規登録）

このページは、検索除外作品のメタデータを確認・補完し、新規作品としてIndexedDBの本棚データへ登録するための画面。既存作品の情報更新には使わない。

入力と読み込み

  • メタデータ欄にJSONまたは項目名付きの通常テキストを貼り付け、「メタデータを読み込む」でフォームに反映する。
  • 通常テキストでは、作品情報ページの表示内容から、Nコード・タイトル・作者名・作者ID・取得元URL・あらすじ・作品状態・エピソード数・ジャンル・掲載日時・最新掲載日時・文字数・開示設定などを読み取る。
  • URLの text、metadata、json パラメータから受信する仕組みもある。ただし、ショートカットからの自動入力が常に成功することを意味しない。現在はメタデータを手動で貼り付ける運用とする。
  • 読み込み後も内容を確認し、不足・誤りがあれば手動で補完する。

登録時の主なチェック

  • Nコード、作品タイトル、取得元URL、開示設定などを検証する。
  • 開示設定に「検索除外中」が確認できない場合は登録を止める。
  • 同じNコードが works_cache に既にある場合は、新規登録を止める。既存作品の編集は別の画面を使う。
  • 作者IDは任意項目。入力時は英数字・アンダースコア・ハイフンを文字列として扱い、数字だけのIDに限定しない。
  • 登録時には本棚のIndexedDBを利用する。登録結果や必須項目の不足は画面のメッセージで確認する。

復旧時の参照先

  • 現行コード：work_add.html を開く
  • 通常作品の自動取り込みページ register.html とは役割が異なる。検索除外作品の新規登録には本ページを使う。
  • コードの変更後は、実際の画面でメタデータ読み込みと登録を確認し、この説明と現行コードに差があれば資料室も更新する。

この節はコード全文の複製ではなく、復旧時に役割・主要な処理・重要な制約を把握するための要約。最新の実装はリンク先のファイルを正本とする。

9. 現在の運用方針

  • JSONを手作業で作成する必要はない。項目名付きの通常テキストを使う。
  • 現時点では、取得したメタデータを新規登録画面へ手動で貼り付ける。自動貼り付けは将来の検討事項とする。
  • 登録画面に情報が自動で入ったように見えても、Nコード・作品名・作者名・あらすじを確認してから保存する。
  • この手順は新規の検索除外作品の登録用。既存作品の情報更新には使わない。
構造記録 共有ショートカット「しおり」の役割と保全（2026年10月25日記録）

1. 基本情報

  • iPhoneのショートカットアプリにある、共有シートから入力を受け取るショートカット。
  • 正式名称：とよむ+しおり
  • 入力テキストの内容に応じて処理を分岐し、note.com のURLと、なろう作品ページの情報を扱う構造が確認できる。
  • ともたは、通常作品・検索除外作品・noteにも使う働き者のショートカットとして「しおり」と呼んでいる。

2. スクリーンショットで確認できた処理

共通の入口

  1. 共有シートから「アプリ、その他18個」を受け取る。入力がない場合は「続ける」。
  2. 「ショートカットの入力」からテキストを取得する。
  3. 取得したテキストに note.com/ が含まれるか判定する。

note.com/ が含まれる場合

  1. テキストからURLを取得する。
  2. URLが「任意の値」の場合の分岐がある。
  3. URLをURLエンコードする。
  4. brave://open-url?url=https://tomotaday.github.io/tomotayomu/index.html?noteUrl=... の形で、ともたよむの本棚URLに noteUrl を付ける。
  5. 組み立てたURLをクリップボードにコピーし、URLを開く。
  6. noteのURLが見つからない場合は「note の URL が見つかりませんでした。」というエラー通知を表示する。

note.com/ が含まれない場合

  1. テキストから syosetu\.com/([^/]+)/ (\d+) に相当する正規表現で一致を検索する。スクリーンショット上では空白なしのパターン syosetu\.com/([^/]+)/(\d+) と読める。
  2. 一致結果のグループ1とグループ2を、それぞれ取得する。
  3. https://tomotaday.github.io/tomotayomu/index.html?ncode=...&episode=... の形のURLを組み立て、URLエンコードする。
  4. brave://open-url?url=... を組み立て、URLを開く。

注：スクリーンショットに表示されたアクションから書き起こした記録。各変数の実際の値や、すべての入力パターンでの動作結果を検証した記録ではない。

3. 分かっていること・未確認のこと

  • 確認できたこと：共有シートからテキストを受け取り、note用とそれ以外で分岐する。note用は noteUrl、なろう用は ncode と episode を付けたともたよむのURLを開く。
  • ともたの運用上の位置づけ：通常作品、検索除外作品、noteを扱う重要なショートカット。
  • 今回の画像だけでは未確認：検索除外作品の情報取得の具体的な分岐・全処理、正規表現が対応するすべてのURL形式、各ルートの例外処理や動作テストの結果。

未確認の部分は推測で補わず、必要になったときに実機の動作と照合して追記する。

4. 保全状況

  • ともたは元のショートカットを複製し、複製側の名前に「保全用」を付けた。
  • 通常使用する版と保全用の複製を分けている。
  • 保全用は、必要がない限り編集・テストに使わず、複製時点の構成を残す方針。
  • 同じiPhone内での複製は誤編集への備えになるが、端末の故障・紛失に備えた別の場所への書き出しや保存とは別。外部へのバックアップは、可能な方法を別途確認する。

5. 復旧・変更時の注意

  • まず「しおり（保全用）」を残し、変更や実験は通常使用版で行う。
  • 変更前後で、note用・なろう用・検索除外作品用の各経路を分けて動作確認する。
  • この資料はスクリーンショットから確認できた構造の記録であり、ショートカット本体のバックアップの代わりではない。
  • 構造や動作が変わったら、実機で確認した内容だけをこの資料に追記する。
