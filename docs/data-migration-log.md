# ともたよむ データ統合・参照先移行記録

最終更新：2026-11-08  
対象バージョン：v3.7.0  
対象リポジトリ：tomotaday/tomotayomu  
目的：既存データを保持したまま、作品データを統合し、読み取り先・書き込み先を項目単位で段階的に移行する。

---

## 1. 絶対ルール

1. 変更前に、この記録へ対象・変更前後・戻し方を記載する。
2. 1項目ずつ、読み取り先と書き込み先を同時に変更する。
3. 変更後は実機で読み取り・書き込みの両方を確認し、結果を記録する。
4. 確認が完了するまで次の項目へ進まない。
5. 旧データ・旧ストア・旧処理は、移行完了と検証が済むまで削除しない。
6. 変更前のコードとGitHubコミットを追跡可能な状態で残す。
7. 本番IndexedDB、localStorage、GitHub Actions、ショートカットに対する操作は、対象と影響を確認してから行う。
8. 新しい統合先へのデータ作成は、既存アプリの読み書き先を変更せずに行う。既存画面から参照されない限り、表示動作は従来どおりとする。

## 7. 運用管理棚と独立データの保護（重要）

運用管理棚そのものは、個々の作品レコードに紐づくデータではない。棚の表示順などは独立したlocalStorage設定で管理される。一方、棚の中に配置された管理機能の一部は、現行の作品DBや独立DBを参照している。

したがって、作品DBの統合・変更によって、運用管理棚やその配下の機能が読み取れなくなることを禁止事項とする。

### 保護対象と注意点

- 運用管理棚の表示・並び順：localStorageの `tomotaYomu_mixed_shelf_order_v1` 等。作品DB移行の対象に混ぜない。
- Atom更新：独立DB `tomotaYomuAtomDB`（entries / meta）を維持する。作者情報の参照先を切り替える場合は、Atom取込・表示の両方を検証する。
- 作者整理：現行 `tomotaYomuDB.authors` を参照する処理がある。作者マスター統合後も、同等の情報を取得できるようにする。
- 本棚管理：現行 `shelf_names` / `shelf_placement` を参照する処理がある。本棚マスターと作品の所属関係を失わない。
- 読書履歴・更新管理・検索除外・ともためも：それぞれの独立DB / localStorageキーの役割を確認し、作品DBへ安易に統合しない。

### 移行方式の追加ルール

1. 旧DB・旧ストアは、切替後も管理機能の参照が残っていないと確認できるまで保持する。
2. 既存管理機能が旧ストアを参照している間は、旧ストアを読み取り専用の互換層として残すか、機能ごとに新しい参照先へ切り替える。
3. 新DBへの統合だけを先行し、既存管理機能の参照先を放置しない。
4. 運用管理棚の各リンクについて、移行前後で起動・読み込み・更新ができることを確認する。
5. 作品データの統合と、管理機能の参照先移行は別々の作業項目として記録する。

**この項目の目的は、DBを整理した結果、日常運用に必要な管理機能が壊れる事態を防ぐこと。**
