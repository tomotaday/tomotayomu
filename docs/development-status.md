### 正本の運用ルール

- DB構造・接続先の詳細は `database-structure.md` に集約する。
- 画面別の読み書き経路は `data-store-usage-inventory.md` に集約する。

- 操作ガイドには必要な手順を記載するが、DB構造などの詳細を重複記載せず正本へリンクする。
- HTML版が必要な資料は、Markdownを唯一の原稿とする生成・同期方式を採用する。方式確定までは手動更新時に差分照合する。

## 4. 記録ステータスの統一

| ステータス | 意味 |
|---|---|
| 未調査 | 対象をまだ確認していない |
| 調査中 | 確認作業を進めている |
| 仕様確定 | ともたとの合意により方針が決まった |
| コード確認済み | 対象コミットのコードで実装・接続を確認した |
| 実機確認済み | 対象環境・操作・結果を実機で確認した |
| 保留 | 意図的に作業を止めている |
| 廃止 | 現行運用から外した。履歴は保持する |

「仕様確定」「コード確認済み」「実機確認済み」は別の状態として扱う。「実装済み」だけで実機確認済みとは判断しない。

各確認記録には、可能な限り対象ファイル・コミットまたはSHA・確認日・確認環境・操作・結果を添える。

## 5. 重要な安全ルール

1. 本番IndexedDB・localStorageを、資料整理や調査のために初期化・削除しない。
2. 旧DB・旧ストア・旧localStorageキーは、参照経路と保全要否が確定し、ともたの承認を得るまで削除しない。
3. GitHub Actions・Shortcut・Atom連携の入口や受け渡し形式を推測で変更しない。
4. 読み取り専用調査と、データを書き換える検証を明確に分ける。
5. 実装・資料更新は小さく分け、変更前SHAを記録する。
6. 実機未確認の事項は「未確認」と記載し、完了扱いしない。
7. 資料室の整備を理由に、アプリ本体の機能・バージョンを不用意に変更しない。

## 6. 現在判明している資料整合性の課題

- `data-store-usage-inventory.md` は本棚管理・作者管理・カクヨム編集・手動登録を旧DB/localStorage中心に記載しており、現行コードと一致しない。
- `database-structure.md` は新DB切替済みの接続表を持つ一方、localStorage表に「カクヨム移行待ち」等の古い記載が残る。
- `database-structure.html` はMarkdown版と接続先・読み書き先の記述が一致しない箇所がある。診断ページへのリンクにも現行ツリーに存在しないファイルが含まれる。
- `repository-structure.md` は現行ツリーに存在しない診断・保守ファイルを記載し、実在するガイド・ツールの一部を掲載していない。
- `repository-structure.html` はMarkdown本文を埋め込む方式だが、内容の更新・同期を継続的に保証する仕組みは未確定。
- 判定センターガイドは旧DBのストアを参照する説明が残り、現行の新DB参照と一致しない。
- なろう登録ガイド等の操作ガイドも、現行コード・Shortcut実機の両面から照合が必要。
