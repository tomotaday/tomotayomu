📘 カクヨム登録・しおりガイド

専用Shortcut、GitHub Actionsによる目次・作品情報取得、新DB登録、作品編集、しおりの流れをまとめた現行ガイド。

現行仕様｜2026-11-14確認
  • 登録専用ShortcutからGitHub Actionsを起動し、登録ページへ移動する。
  • Actionsが目次と作品メタデータを取得・検証し、登録ページが完了結果を待って読み込む。
  • 登録ページの明示操作で新DB tomotaYomuWorksDB version 2 の works に保存する。
  • 既存のしおりShortcut「とよむ+しおり」は従来の受け渡しを維持する。

登録・カードリンク・しおりは実機確認済み。作品ごとの目次取得結果は、実行結果と対象作品で確認する。

1. 登録専用Shortcutの構造（2026-11-14画面確認）

Shortcut名は「とよむ←カクヨ…」（画面上の表示は省略形）。今回確認できたアクションを、画面に写っている順に記録する。

  1. 「共有シートからアプリ、URLを受け取る」。入力がない場合は「続ける」。
  2. 変数 work_url に「ショートカットの入力」を設定する。
  3. キーチェーンから GitHub_PAT を取得し、変数 token に設定する。
  4. GitHub_PAT の値がない場合は「GitHub Personal Access Tokenを入力してください」でテキスト入力を要求し、入力値を token に設定して、キーチェーンへ GitHub_PAT として保存する。
  5. If文を終了する。
  6. Generate UUID でUUIDを生成する。
  7. GitHub APIのWorkflow dispatchエンドポイントへPOSTする。URLは https://api.github.com/repos/tomotaday/tomotayomu/actions/workflows/kakuyomu-toc.yml/dispatches、ref は main、本文はJSON。
  8. JSONの inputs は2項目。work_url に変数 work_url、request_id に生成したUUIDを設定する。
  9. request_id をクエリに含む登録ページURLをテキストとして作成し、そのテキストを開く。

スクリーンショットで確認できた範囲の記録。HTTPリクエストのヘッダは、Authorization = Bearer ＋変数 token、Accept = application/vnd.github+json、X-GitHub-Api-Version = 2022-11-28。PATの実値は資料に記載しない。画面に写っていない後続アクションや追加設定は未確認として扱い、推測で補わない。

2. Actions実行後の登録処理

  1. Shortcutが次の登録ページを開く。URL中のUUIDはActions実行と登録ページを結びつける照合キー。
  2. GitHub Actionsがカクヨムの作品情報と目次を取得し、作品ID・公表総話数・抽出件数・連番・重複エピソードIDを検証する。
  3. 登録ページは結果JSONを5秒間隔で確認する。最大60回（最大約5分）待ち、成功結果を受け取ると検証済みTOCと作品メタデータを読み込む。
  4. 登録ページで作品情報・登録先を確認し、「本棚へ登録」を実行する。登録ページを開いただけでは作品は保存されない。
https://tomotaday.github.io/tomotayomu/app/kakuyomu/kakuyomu_write.html?request_id={UUID}

「1/60」などの表示は、作品の話数やActionの工程数ではなく、5秒ごとの完了確認回数。

3. 取得する作品情報

Workflowの work_metadata から、タイトル、作者表示名、作者ハンドル、あらすじ、タグ、作品状態、文字数、最終更新日、初回掲載日等を登録画面へ渡す。

  • 作者ハンドルは author.name 由来の値を @ なしで保存する。表示上の @ は必要な場合に画面側で付ける。
  • 作者ハンドルは作者プロフィールURLの識別子として扱う。既存作品の編集で変更する場合を除き、通常の作品情報更新で上書きする仕様ではない。
  • あらすじは初回登録時に取得する。現行の定期更新・目次再取得で既存作品のあらすじを自動更新する処理はない。必要に応じて編集画面で手動修正する。
  • 総話数は検証済みTOCの episodes 件数を採用する。

5. 本棚表示・しおり

  • 本棚カードの作品リンクは対象作品のカクヨムURLを開く。
  • しおりShortcut「とよむ+しおり」はエピソードURLを受け取り、作品ID・エピソードID・URLを本棚データへ保存する。
  • 作品別TOC JSONのエピソードIDと保存済みしおりを照合し、読了話数／総話数を表示する。
  • TOCが取得できない場合やエピソードIDが見つからない場合は、話数を確定できない。検証済みTOCと一致しない値を総話数の根拠にしない。

6. 保存先・編集

  • 作品レコード：IndexedDB tomotaYomuWorksDB version 2 の works。
  • 作品IDを含むレコードID：kakuyomu:{作品ID}。
  • 作者ハンドル：作品レコードの authorId。互換情報として siteData.legacyFields.authorHandle にも保存。
  • あらすじ等のサイト固有情報：作品レコードの synopsis / siteData。
  • 作品編集ページ：app/kakuyomu/kakuyomu_edit.html。新DBの対象作品を読み込み、編集内容を works へ保存する。

安全上の注意

  • GitHub Actionsの秘密情報をGitHub PagesのJavaScriptへ埋め込まない。
