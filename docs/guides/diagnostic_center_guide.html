🧭 判定センター 運用・判定基準ガイド

本棚作品のNコード抽出、API照会、作者Atom取得失敗の確認に使う診断ページの運用と安全方針。

現行構成｜2026/11/14確認

画面：tools/diagnostic/ncode_extract.html

作品データは新DB tomotaYomuWorksDB version 2 の works を読み取る。DBが存在しない場合や構造が想定外の場合は処理を中止し、DBを新規作成しない。

判定センターを開く ↗

1. 設置目的

  • 新DBに登録されたなろう作品からNコードを抽出し、形式不正・重複等を確認する。
  • 通常API・R18 APIで作品の取得可否を調べる。
  • 検索除外リストと照合し、未検出を分類する。
  • 作者Atomの取得失敗を確認し、作者ページを人が確認した結果を記録する。
  • 作者に関連する本棚作品を確認する。診断結果だけで作品・作者を自動削除しない。

2. 保存先・参照先

項目現行コードでの接続
作品DBtomotaYomuWorksDB v2 / works。site === "narou" の作品を抽出。
検索除外localStorage tomotaYomu_search_excluded_ncodes_v1 を読み取り。
全件判定の進捗localStorage tomotaYomu_diagnostic_fullcheck_v1。
作者確認記録localStorage tomotaYomu_diagnostic_atom_audit_v1。
作品確認記録localStorage tomotaYomu_diagnostic_work_audit_v1。
Atom入力公開JSON data/atom/author-feeds.json。

診断進捗・確認記録は診断ページを開いたブラウザのlocalStorageに保存される。別ブラウザ・別端末とは自動同期しない。判定センターは旧DBの shelf_placement / works_cache / authors を現行作品の正本として使用しない。

3. 主な機能

① 新DBからNコードを抽出

  • 既存DB tomotaYomuWorksDB を開き、works を読み取る。
  • site === "narou" の作品から workId を取り出す。
  • 形式不正・重複を分けて集計する。作品レコードの追加・変更・削除は行わない。
  • DBが存在しない場合、IndexedDBの一覧を確認できないブラウザ、DB versionやstoreが想定外の場合は安全のため停止する。

② API一括判定（試験）

抽出したNコードの先頭最大1,000件を対象に、通常APIとR18 APIで照会する試験機能。

③ 全件判定（再開対応）

  • 100件単位に分けて照会する。
  • 通常APIで見つからなかったコードをR18 APIでも照会する。
  • 途中結果を診断専用localStorageへ保存し、同じ対象一覧で再開できる。
  • 進捗の消去操作は診断専用の一時進捗だけを対象とする。作品DBの削除ではない。

④ Atom取得失敗の確認

  • 公開Atom JSONから取得失敗した作者・フィードを表示する。
  • 作者ページを開き、人が目視確認した結果を診断専用localStorageへ記録する。

⑤ 作者に関連する作品の確認

  • 新DB works を読み、作者ID・作者種別等で関連作品を抽出する。
  • 作品ページを開いて確認し、必要に応じて「削除確認済（未実施）」を記録する。
  • 確認記録は削除処理を実行しない。

4. API判定の考え方

結果意味・扱い
通常API取得通常APIで取得できた。API上で存在を確認できた状態。
R18 API取得通常APIでは見つからず、R18 APIで取得できた状態。
検索除外・未検出通常API・R18 APIの両方で未検出、かつ検索除外リストに登録されている。削除を意味しない。
要確認・未検出両APIで未検出、かつ検索除外リストにない。WEBでの確認が必要。
API未検出 ＝ 作品削除ではない

検索除外、公開状態の変化、API側の一時的な問題、取得条件など複数の可能性がある。通信エラー・応答形式不正・件数不一致は未検出とせず、判定を中断して再確認する。

5. 作者・作品のWEB確認

  1. カードのWEB確認ボタンから対象ページを開く。
  2. ページを人が目視し、取得失敗や削除表示の有無を確認する。
  3. 確認できた場合だけ該当する確認済みボタンを押す。
  4. 確認記録は同じブラウザのlocalStorageに保存され、表示上の二重操作防止に使われる。
  • Atom取得失敗は、作者退会の確定ではない。
  • HTTP 404だけで退会確定にしない。作者ページを実際に開いて確認する。
  • 「削除確認済（未実施）」は人による確認記録であり、削除処理の実行を意味しない。

6. 安全方針

  • 作品DB tomotaYomuWorksDB は読み取り専用で開く。作品・棚の追加・変更・削除をしない。
  • 診断専用の進捗・確認記録だけをlocalStorageへ保存する。
  • 検索除外リストは読み取り専用。診断ページから正本を書き換えない。
  • 作者・作品を自動削除しない。
  • 判定結果だけを根拠に本棚データを変更しない。
  • 本体・Shortcut・GitHub Actionsの入力形式を診断目的で変更しない。

7. 実機確認の記録

2026/11/10、iPhone / Braveで新DBからなろう作品3,596件を抽出し、形式不正0件・重複Nコード0件を確認した記録がある。これは当時の実機確認値であり、現在のDB件数を固定するものではない。

現行ページのコードと本資料が食い違う場合は、まずコードを読み取り確認し、実機での再確認が必要な点を分けて記録する。
