1. 設置目的

本棚に登録された作品や作者について、API・Atomから取得できない原因を調べ、実際にWEBページを確認するための診断窓口。API取得失敗をそのまま削除・退会と断定せず、人が確認して記録する。

  • 作者Atomの取得失敗と、作品APIの生存確認を分けて扱う。
  • 作者の状態を確認したうえで、その作者IDに関連する本棚作品を照合する。
  • 本棚全作品をまとめて照会し、確認が必要なNコードを抽出する。
  • 検索除外リストとの照合結果を表示し、未検出理由の切り分けを助ける。
  • WEBで確認した記録を残す。ただし作品削除などの実処理は行わない。

3. 判定センターの構成項目

① 本棚からNコードを抽出

  • 既存のIndexedDBを読み取り専用で開く。
  • shelf_placement と works_cache を読み、Nコードを抽出・重複除去する。実際のAPI照会対象は、両方のストアに存在するNコード。
  • 配置側にだけ存在するコード、作品キャッシュ側にだけ存在するコード、形式不正の件数を分けて表示する。
  • 抽出結果の先頭20件・全件を確認、コピーできる。

② API一括判定（試験）

抽出した照会対象Nコードの先頭最大1,000件を対象に、通常APIとR18 APIで照会する試験機能。全件判定とは別の、先頭部分で動作を確認するための機能。

③ 全件判定（再開対応）

  • 全Nコードを100件単位に分割して照会する。
  • 通常APIで見つからなかったコードだけをR18 APIへ照会する。
  • 100件単位の完了結果をブラウザ内に一時保存し、中断時は同じNコード一覧で再開できる。
  • 全件完了後、件数集計と判定結果一覧を表示する。詳細一覧は折りたたみ表示。

④ Atom取得失敗の確認

  • 最新のAtom取得結果JSONを読み、作者またはフィードが失敗した作者を表示する。
  • 作者ID・全年齢/R18区分・作品Atom/活動報告AtomのHTTP状態を表示する。
  • WEB作者ページを開き、目視確認後に「作者退会確認済」を記録する。

⑤ 作者に関連する本棚作品

  • IndexedDBの authors と works_cache を読み取り、作者IDと全年齢/R18区分を照合して関連作品を抽出する。
  • 該当作品のタイトル・Nコード・判定結果をカード表示する。
  • 作品WEBページを開いて確認できる。
  • 条件を満たす未検出作品について「削除確認済（未実施）」を記録できる。

4. 作品APIの判定基準

結果意味・扱い
通常API取得通常APIで取得できた。API上で存在を確認できた状態。
R18 API取得通常APIでは見つからず、R18 APIで取得できた。R18 API側で存在を確認できた状態。
検索除外・未検出通常API・R18 APIの両方で未検出、かつ検索除外リストに登録されている。削除を意味しない。
要確認・未検出通常API・R18 APIの両方で未検出、かつ検索除外リストに登録されていない。WEBでの確認が必要。
重要：API未検出 ＝ 作品削除ではない

検索除外、公開状態の変化、API側の一時的な問題、取得条件など複数の可能性がある。APIの未検出だけで削除確定にしない。通信エラー・応答形式不正・件数不一致は「未検出」とせず、判定を中断して再確認する。

5. Atom・作者の判定基準

  • Atom取得失敗は「フィードを取得できなかった」という事実であり、作者退会の確定ではない。
  • HTTP 404も、それだけで退会確定にしない。作者ページをWEBで開いて表示内容を確認する。
  • 作者ページで退会表示を目視確認した場合に限り、「作者退会確認済」を記録する。
  • 作者退会確認後、その作者IDに紐づく本棚作品を照合する。

例：2026/11/07の実機確認では、作者ID X2602BO（R18）の作品Atom・活動報告AtomがHTTP 404となり、WEB確認後に作者退会確認済の記録が行われた。

6. WEB確認と確認済みボタン

  1. カードのWEB確認ボタンから、対象の作者ページまたは作品ページを開く。
  2. WEBページを人が目視し、取得失敗の原因・削除表示の有無などを確認する。
  3. 確認できた場合だけ、該当する確認済みボタンを押して記録する。
  4. 記録後は確認ボタンをグレー表示・無効化し、二重操作を防ぐ。
  • 作者カード：作者退会確認済の記録後、「取得失敗を確認する」ボタンを無効化する。
  • 作品カード：削除確認済（未実施）の記録後、「作品を確認する」ボタンを無効化する。

ボタンの無効化は診断記録に基づく表示制御。WEBページの状態を自動監視・再検証するものではない。記録は同じブラウザのlocalStorageに保存される。

7. 安全方針・変更禁止事項

判定センターの大原則
  • 本棚のIndexedDBは読み取り専用。新規作成・追加・更新・削除をしない。
  • 本体の index.html に診断処理を持ち込まない。入口リンク以外の本体機能を改変しない。
  • Atom本番処理・GitHub Actionsの取得処理を変更しない。
  • 検索除外リストを診断ページから変更しない。
  • 作品・作者を自動削除しない。
  • 「削除確認済（未実施）」は人がWEBで確認した記録であり、削除処理を実行した意味ではない。
  • 判定結果・確認記録は診断専用領域に保存し、本棚の正本データと分離する。

9. 現在の実装範囲と今後の確認事項

実装済み（コード上）

  • 既存本棚DBからのNコード抽出・集計
  • 通常API→R18 APIの順での照会
  • 100件単位の全件判定・一時保存・再開
  • 検索除外リストとの照合・未検出分類
  • Atom取得失敗作者の表示、作者ページ確認、退会確認記録
  • 作者に関連する本棚作品の表示、作品ページ確認、削除確認済（未実施）の記録
  • 判定結果一覧の折りたたみ、確認済みボタンの無効化

引き続き確認・検討する項目

  • 検索除外リストの正本と診断ページが読むlocalStorageデータの同期・一致確認。
  • 作者退会確認後に表示される関連作品の全件照合と、作品カードの操作条件。
  • 診断記録を端末変更・ブラウザ変更後も参照する必要があるか。現状は同一ブラウザ内の保存。
  • 閲覧可能／要再確認／閲覧不能の疑い／判定不能といった、より細かなWEB確認結果の分類は今後の設計候補。現行コードの確定済み判定区分とは区別する。

この資料は2026/11/07時点の設計方針と実装コードを整理したもの。実機での動作確認が完了した項目は、確認日と結果を追記して更新する。
