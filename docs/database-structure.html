注意：コードで確認できた構造と、ブラウザ実機の診断が必要な項目を分けて記載する。未確認のkeyPathは推測しない。旧DB・旧localStorageは全機能の移行と実機確認が終わるまで削除しない。

2. 共通作品レコード

  • 識別：id（例：narou:N1234AB）、site、workId
  • 共通情報：title、author、authorId、shelfId
  • 読書状態：reading.position / reading.isRead
  • サイト固有しおり：bookmark
  • サイト固有情報：siteData
  • 未分類：shelfId 空欄。専用の未分類作品IDは作らない。
  • reading と bookmark は別用途。読書進捗とサイト上のしおりURLを混同しない。

5. 変更時の確認ルール

  1. 対象画面の読み取り先・書き込み先を両方確認する。
  2. DB名・version・store・keyPath・indexを変える場合は専用移行を行い、既存データ件数と再読込結果を照合する。
  3. 一度に一機能ずつ切替え、Brave実機で表示・保存・再読み込みを確認する。
  4. 旧DB・旧localStorageは全機能の移行と実機確認が終わるまで削除しない。
  5. 変更後は本ページ、repository-structure、data-store-usage-inventory、data-migration-logを同じ作業で更新する。
  6. 不明なkeyPathや未確認の接続は「未確認」とし、推測で埋めない。
