- 旧判定は `current != null && total > 0 && current < total`。bookmark=nullの完全未読作品は先頭条件で除外されていた。

## 8. なろう作品の削除機能「🗑️ ごみばこ」設計（2026-11-23）

### 決定した方針

- 表示名称は **「🗑️ ごみばこ」**。漢字の「ゴミ箱」ではなく、ひらがな表記を採用。柔らかく親しみやすい印象を意図した名称。
- 対象はなろう作品のみ。カクヨム・noteは今回対象外。
- 削除方法は論理削除と物理削除の両方を用意する。
- ごみばこはシステム専用機能。ユーザー作成の通常棚とは別で、「保留棚」とも完全に分離する。
- ごみばこ作品は通常の全作品一覧・通常棚・未分類・🆙更新棚・検索結果に表示せず、通常の全作品件数にも含めない。ごみばこ専用画面だけに表示する。
- ごみばこへ入れる操作は、通常棚への移動とは別の削除操作とする。
- ごみばこ内では「↩️ 元に戻す」と「完全削除」を用意する。完全削除は1作品単位で、バックアップと二段階確認を行う。一括完全削除は初回実装に含めない。

### 論理削除データ案

- `deletedAt`：削除日時。
- `previousShelfId`：削除直前の棚ID。
- `shelfId`：ごみばこ中は空文字 `""` とする案。
- bookmark・作品情報・作者情報等は保持。
- 復元時は削除前の棚へ戻す。削除前が未分類なら未分類へ戻す。
- これらのフィールド名・保存形式は、全保存経路とバックアップ互換性の監査後に最終確定する。

### 実装前に残る調査

1. 全件API取込・個別API更新・新規登録・補完など、worksへの全書き込み経路で削除状態が消えたり、作品が通常表示へ復活したりしないこと。
2. 通常カード生成・全作品件数・棚・検索・更新棚・読書履歴などの読み取り経路から、ごみばこ作品を除外できること。
3. 更新候補・検索除外・Atom等の独立データに対象作品が残る場合の扱い。作者全体や他作品の情報を誤って削除しないこと。
4. 完全削除時のバックアップ・対象一意特定・二段階確認。
5. エクスポート・バックアップ・復元処理との互換性。
