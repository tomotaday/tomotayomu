## 3. 39作品の項目整理方針

対象は、今回の検査で旧 `reading` が残存している39作品に限定する。3,701作品全体やごみばこ164作品を一括変更しない。

### 合意した処理

| 旧項目 | 処理方針 |
|---|---|
| `reading` | 旧値を `bookmark` に上書きした後、削除 |
| `characterCount` | 削除 |
| `updatedAt` | 39作品の `publishedAt` と `lastPublishedAt` が有効な日付であることを確認後、削除 |
| `createdAt` | 最新検査で本棚内残存0件。今回対応不要 |

重要事項：

- `reading` は既存の `bookmark` より旧 `reading` の値を優先し、39作品の `bookmark` を上書きする方針。
- 上書きの具体的な値変換は、現在の正規bookmark形式と39作品のreading実データを照合してから実装する。値の形を推測してコピーしない。
- 変更前に39作品のレコードをバックアップし、対象Nコード・件数・変換後プレビューを確認する。
- 日付検査に1件でも不正・欠損があれば、旧 `updatedAt` の削除は保留し、対象と値を確認する。
- 本番IndexedDBへの書き込みは、バックアップ・プレビュー・対象件数の確認後に行う。

## 4. 検索除外作品の新規登録・変更登録も監査する

- `legacyFields` を互換用の格納先として残さない。
- `siteData` 自体はサイト固有情報の正規格納先として維持する。`siteData.legacyFields` は廃止対象。

## 9. 2026-11-28 作者管理の集計基準を新works正本へ統一（15:20頃）

### 変更の背景

作者管理ページの集計・JSON出力で、次の問題が確認された。

- なろう作品の作者名・作品名・R18判定に `siteData.legacyFields` へのフォールバックが残っていた。
- ごみばこ作品も作者一覧・作者数・作品数・GitHub用作者JSONの対象に含まれていた。
- 作者JSONの作者種別を `authorType` の値だけで判定し、未設定値を全年齢として扱っていた。
- 作者IDに複数の `authorType` が混在する場合、同じ作者IDが全年齢・R18の別キーで二重計上される可能性があった。

### ともたが確定した集計方針

- **検索除外作品は作者管理に含める。**
- **ごみばこ作品だけを作者管理から除外する。**
- なろう作品の作者管理は新works正本 `tomotaYomuWorksDB` / `works` を参照する。
- なろうの旧 `legacyFields` は参照しない。
- R18判定と作者種別の基準は `siteData.isR18` とする。

### 実装内容

対象ファイル：`app/author/author.html`  
バージョン：`3.1.0.14`  
コミット：`8b062c10685e7ef45cb387bb2c281d65ebf4ea30`

1. `adaptWork()`
   - 作品名はトップレベル `title` のみ。
   - 作者名はトップレベル `authorName` のみ。
   - R18判定は `siteData.isR18 === true` のみ。
   - `legacyFields` への参照を撤去。

2. 作者管理対象
   - `site === "narou"` かつ `deletedAt` がない作品を対象とする。
   - 検索除外リストによる除外は行わない。
   - ごみばこ作品は一覧・作者数・作品数の対象外。

3. 作者情報の保存対象
   - 作者管理名・ふりがな等の作者情報更新も、ごみばこ作品を更新対象から除外。
   - 現役作品に紐づく同一作者IDの作品を対象にする。

4. ふりがな取得
   - ごみばこ作品を除外。
   - `authorType` ではなく `siteData.isR18` を基準に全年齢作者を抽出。

5. 作者登録処理
   - 作者APIとの照合対象は、ごみばこではない現役なろう作品。
   - 作者APIからの作者情報保存もごみばこ作品を更新しない。

6. GitHub作者JSON
   - ごみばこ作品を除外。
   - 検索除外作品は含める。
   - 作者種別は `siteData.isR18 === true` なら `r18`、それ以外は `normal` とする。
   - 作者IDと種別を組み合わせたキーで重複を排除する。
