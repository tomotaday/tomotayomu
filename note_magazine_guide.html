📝 note登録・更新・復旧ガイド

noteマガジンのURLを共有シートから受け取り、GitHub Actionsで目次JSONを作成し、ともたよむの本棚へ登録・更新する仕組み。

現行方式：手動同期（マガジン単位）
2026/10/30 動作確認済み

note側で新着記事を見つけたら、マガジントップを共有してショートカットを実行する。自動巡回ではない。GitHub Actionsの成功と、登録画面での目次表示まで確認済み。

1. 全体の処理の流れ

  1. Braveでnoteのマガジントップを開く。
  2. 共有シートからショートカット 「ともたよむ note」 を実行する。
  3. ショートカットが共有URLを受け取り、保存済みGitHub Personal Access Token（PAT）を取得する。
  4. GitHub REST APIへPOSTし、note-magazine-index.yml のworkflow_dispatchを実行する。
  5. GitHub Actionsがnote APIからマガジン詳細と記事一覧を取得し、data/note-index-マガジンID.json をmainブランチへ保存する。
  6. ショートカット末尾で、受信URLをURLエンコードして note_magazine_add.html を開く。
  7. 登録画面がJSONを読み込み、マガジン名・作者名・記事一覧を表示する。
  8. 内容を確認して「本棚に登録」または「目次を更新」を押す。ここで初めて、この端末の本棚データへ反映される。
重要：GitHub Actionsの成功だけでは、本棚への登録・更新は完了しない。JSON作成と、登録画面での確定操作は別工程。

2. 関係するファイル・保存先

  • .github/workflows/note-magazine-index.yml：GitHub Actions。URL検証、note API取得、目次JSON保存。
  • note_magazine_add.html：受け渡し・確認・登録画面。JSONを読み、表示名を確認して本棚へ登録する。
  • data/note-index-{magazineKey}.json：マガジンごとの取得結果。記事タイトル、記事URL、記事キー、公開日時、ページ情報などを保存。
  • 端末内 localStorage tomotaYomu_note_magazines_v1：本棚に登録したnoteマガジンの管理情報。
  • 端末内 IndexedDB tomotaYomuDB：登録時に未分類棚のIDを参照するために使用。

noteマガジンの一覧管理情報はこの端末のlocalStorageに保存される。GitHub上のJSONは取得目次の共有データであり、端末内の登録状態そのものではない。

3. GitHub Actionsの仕様

  • Workflow名：noteマガジン目次取得（汎用）
  • Workflowファイル：.github/workflows/note-magazine-index.yml
  • 起動方式：workflow_dispatch
  • 必須入力：magazine_url（共有されたマガジンURL）
  • 対象URL形式：https://note.com/{ユーザーID}/m/{マガジンID}
  • 記事取得API：https://note.com/api/v1/layout/magazine/{ID}/section?page=N
  • 最大30ページまで取得し、is_last_page がtrueになったページで終了。
  • 記事0件、最終ページ未到達、API応答形式の異常などはエラーとして保存を中止する。
  • 保存先：data/note-index-{ID}.json。既存ファイルがあれば更新する。

マガジン詳細APIから表示名・作者名も取得を試みる。取得できない場合でも目次取得は続行し、登録画面で表示名を入力・修正できる。

4. ショートカット「ともたよむ note」アクション一覧

2026/10/30に共有された実機スクリーンショットと、動作確認した構成を記録。PATの実値は記録しない。

  1. 共有シートから入力を受け取る
    受け取る種類：アプリ、URL（共有シートからnoteマガジンURLを受け取る）。入力がない場合は「続ける」。
  2. 「GitHub_PAT」を取得
    iOSショートカットの保存領域から既存トークンを取得する。
  3. 変数 token を設定
    取得したGitHub_PATを変数 token に入れる。
  4. If：GitHub_PAT の値がない場合
    「GitHub Personal Access Tokenを入力してください」でテキストを要求し、指定入力を token に設定。続けて token を GitHub_PAT として保存し、Ifを終了する。
  5. URLの内容を取得（POST）
    送信先：https://api.github.com/repos/tomotaday/tomotayomu/actions/workflows/note-magazine-index.yml/dispatches
    方式：POST。ヘッダーはAtom更新ショートカットで成功しているGitHub認証・Accept・APIバージョン設定を引き継ぐ。認証値は Authorization: Bearer [token]。
    JSON本文は ref = main、inputs.magazine_url = ショートカットの入力。
  6. URLエンコード
    入力：ショートカットの入力。共有されたマガジンURLをエンコードする。
  7. テキスト
    固定文字列 https://tomotaday.github.io/tomotayomu/note_magazine_add.html?noteMagazineUrl= の末尾に、直前の「URLエンコード済みのテキスト」を変数として差し込む。
  8. URLを開く
    直前のテキストを開く。これにより登録画面へ移動する。
復旧時の注意：Atom用ショートカットの「クリップボードからテキストを取得」はnote版では使わない。note版は共有シートから受け取ったURLを最後まで使う。末尾のURL組み立ては「ショートカットの入力」そのものではなく、「URLエンコード済みのテキスト」を差し込む。

5. JSON本文の形

{
  "ref": "main",
  "inputs": {
    "magazine_url": "共有シートから受け取ったマガジンURL"
  }
}

「共有シートから受け取ったマガジンURL」は説明用の表現。ショートカットでは文字列を手入力せず、マジック変数「ショートカットの入力」を設定する。

6. 登録画面での操作

  1. 緑色の「目次を取得しました」が表示されることを確認。
  2. 本棚に表示するマガジン名と作者名を確認・必要に応じて修正。
  3. 記事一覧・取得件数・最終ページ・取得日時を確認。
  4. 初回は「本棚に登録」。登録済みなら「目次を更新」と表示される。
  5. ボタンを押した後、「本棚への登録が完了」または「登録済みマガジンの情報を更新」の表示を確認。
  6. 本棚へ戻り、note棚の作品カードと目次を確認。

目次確認だけで止めたい場合は、登録ボタンを押さない。登録画面を開いただけでは本棚データは変更されない。

7. 更新時の運用

現行はマガジン単位の手動同期。note側で新着記事を見つけたら、該当マガジンのトップページを共有して同じショートカットを実行する。別の更新専用ショートカットは不要。

  1. 更新を見つけたマガジンのトップを共有。
  2. 「ともたよむ note」を実行。
  3. Actionsの成功を確認し、登録画面で新しい記事数・記事一覧を確認。
  4. 「目次を更新」を押す。
  5. 本棚カードの目次を開き、新着記事が追加されているか確認。

記事単位ではなく、マガジン全体の目次を再取得する。これにより記事の追加・順序変更をまとめて反映する。

8. トラブル時の確認順

  1. 「マガジンURLが届いていません」
    ショートカット末尾のテキストに固定URLとエンコード済みテキストが連結されているか。URLを開くアクションがそのテキストを開いているか確認。
  2. Actionsが起動しない／失敗する
    POST先のworkflowファイル名、POST方式、ヘッダー、JSONの ref: main と inputs.magazine_url を確認。PATをチャットや資料へ貼らない。
  3. Actionsは成功したが登録画面に目次が出ない
    リポジトリの data/note-index-{マガジンID}.json が作成・更新されたか、magazineKey がURLのIDと一致するか、items が1件以上あるか確認。公開反映を待って再読み込み。
  4. マガジン名がID表示・空欄
    登録画面で表示名を手入力してから登録する。作者名は任意。
  5. 本棚に反映されない
    登録画面の確定ボタンを押したか確認。Actions成功だけでは端末内の本棚登録は完了しない。
  6. 更新ボタンが「本棚に登録」のまま
    同じ端末・同じブラウザのlocalStorageに既存マガジン情報があるか確認。BraveとSafariは保存領域が別になる場合があるため、登録したブラウザで確認する。

9. 現在の確認状況・未確認事項

  • 共有シートからマガジンURLを受け取る。
  • GitHub ActionsをPOSTで起動し、成功する。
  • 目次JSONを取得し、登録画面でマガジン名・作者名・記事を表示する。
  • 登録後、note棚の作品カードに表示され、目次・しおりURLが確認できる。
  • 未確認：新着記事を追加した後、同じショートカットで再取得し「目次を更新」したときの差分反映。
  • 未実装：note更新の自動検知・自動巡回。

復旧の基本方針：まず成功済みのショートカット構造を保ち、問題のある工程だけを確認する。PATの再発行やヘッダーの変更など、必要性が確認できない変更は行わない。
