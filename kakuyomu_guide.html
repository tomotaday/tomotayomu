📘 カクヨム登録・しおりガイド

カクヨム作品をともたよむへ登録し、読書位置をしおりとして保存する仕組み。

現状：実装済みの構成

2026/11/01時点。画面・コードで確認できた内容と、ショートカットのスクリーンショットで確認できた内容を記録。

1. 作品登録用ショートカット

  1. 共有シートから入力を受け取る。
  2. ショートカットの入力からテキストを取得する。
  3. テキストを使った取得処理を行う。
  4. 取得結果をテキストにまとめる。
  5. そのテキストをクリップボードにコピーする。
  6. kakuyomu_add.html を開く。

上記は共有されたショートカット画面で確認できたアクションの並び。取得アクションの内部設定・取得対象の詳細までは、画面から確定できていない。

2. 作品登録画面

kakuyomu_add.html は、カクヨム作品情報のテキストと作品URLを受け取り、解析結果を確認・修正して本棚へ登録する画面。

  1. 作品情報テキストを貼り付ける。
  2. カクヨム作品ページのURLを貼り付ける。
  3. 作品情報を解析する。
  4. 作品ID、タイトル、作者名、作者ハンドル、あらすじ、タグ、作品状態、総話数、文字数、最終更新日を確認・修正する。
  5. 登録先の本棚を選択し、本棚へ登録する。

登録データは端末内のlocalStorage tomotaYomu_kakuyomu_works_v1 に保存される。登録先の本棚は tomotaYomuDB の棚情報から読み込む。

3. しおり用ショートカット

既存の「とよむ＋しおり」にカクヨム分岐を追加済み。

  1. 共有テキストに kakuyomu.jp/works/ が含まれるか判定する。
  2. 共有テキストからURLを取得する。
  3. URLをURLエンコードする。
  4. 次のURLを作成してBraveで開く。
https://tomotaday.github.io/tomotayomu/index.html?kakuyomuUrl=エンコード済みURL

ともたよむ側では受け取ったURLから作品ID・エピソードIDを解析し、登録済み作品のしおりURLとして保存する。旧形式の kakuyomuId と episodeId による受け取りも互換性のため残している。

4. カクヨム目次の取得と話数表示

しおりURLに含まれるエピソードIDを、作品の何話目かに変換するため、GitHub Actionsで作品目次を取得して保存する。

  1. ともたよむ本棚の「⚙️管理設定用」を開く。
  2. 「カクヨム目次取得」を開く。
  3. GitHub Actions画面で「Run workflow」を押す。
  4. 作品ID欄に、登録済みカクヨム作品の作品IDを入力して、もう一度「Run workflow」を押す。
  5. 処理が成功すると、目次JSONが data/kakuyomu-toc/作品ID.json としてGitHubへ保存される。
  6. ともたよむを再読み込みすると、保存済み目次からしおりのエピソードIDを照合し、「続き📖345/1,132話」のように表示する。

目次取得は作品ごとに実行する。初期値には検証用作品IDが入っているため、新しい作品を試すときは必ずその作品のIDに変更する。取得時には、検証用作品の先頭10話のID・順序と、カクヨム公表話数との一致を確認する。不一致の場合は不完全なJSONを保存せず、Actionsを失敗として止める。目次JSONが未取得・未照合の場合は、従来の表示のままになる。

GitHub Actions：カクヨム目次取得を開く

5. 本棚カードの表示

カクヨム作品カードは、しおりURLに含まれるエピソードIDを作品別目次JSONと照合し、話数を自動表示する。

続き📖345/1,132話

「続き📖」のリンクから保存済みエピソードを開く。編集画面では「しおり（読了話数）」の手入力欄を廃止し、しおりURLを正として扱う。目次未取得・未照合の場合は、その状態を表示する。

これから目指すこと

  • 登録用ショートカットから登録画面への情報受け渡しを簡単にし、手動コピー・貼り付けを減らす。
  • 登録時に必要な情報の取得・入力手順を整理し、登録作業を短縮する。
  • しおり取得から本棚カードの続き表示・再開までを一連の操作として安定させる。
  • なろう・note・カクヨムの作品カードと管理操作の共通部分を整理する。ただし各サイト固有の取得・保存処理は分離して維持する。
